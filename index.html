One small setup, five open terminals.

01

Deploying a static site means SSH, git pull, rsync scripts, hand-edited nginx configs.

02

A redirect means touching conf.d/ and praying nginx -t passes.

03

TLS certs are certbot cron jobs you set up once and hope never break.

04

A new DB user means psql as root, typing GRANT from memory.

05

.env files scattered across machines, no history, no source of truth.

06

Maintenance scripts buried in crontabs nobody remembers editing.

Each is simple alone. Together they turn a small setup into a part-time job — and every manual step is a typo away from breaking production. Quaykeeper replaces all of it with one console.

// how it's built

The policy & UI layer for infra you already run.

Quaykeeper sits next toyour infrastructure, never inside it. It drives nginxpilot over a REST API and talks to your databases directly — it never touches the web server's filesystem. State lives in a single SQLite file: no external database, no message queue, no Kubernetes.

Deliberately small, deliberately inspectable, deliberately yours.

[01]
Never in the request path
Quaykeeper can be down; your sites keep serving. It only orchestrates.
[02]
Secrets go one way
Tokens, keys and passwords are accepted, encrypted or hashed, and never read back out.
[03]
Fail closed
Domain verification, webhook signatures, fragment validation — every gate defaults to no.
[04]
Boring persistence
One SQLite file with WAL and ordered migrations. Back it up with cp.
[05]
Owner-gated power
Anything touching the host — certs, tasks, realms — needs the highest role and is audited.

// get started

Two containers. Started in order. You're the owner.

Step 1brings up nginxpilot, so there's something for Quaykeeper to manage. Step 2 brings up Quaykeeper — point it at a GitHub OAuth app, sign in, and the first login becomes the owner.

Both are one SQLite/file-backed container each. Back either up with cp.

Step 1 — nginxpilot guideStep 2 — Quaykeeper guide
# step 1 — start nginxpilot first
docker pull ghcr.io/kalevski/toolcase/nginxpilot:latest
docker network create nginxpilot-net
docker run -d --name nginxpilot \
--network nginxpilot-net \
-p 80:80 -p 443:443 \
-e ADMIN_TOKEN="$(openssl rand -hex 32)" \
-v nginxpilot-data:/data \
ghcr.io/kalevski/toolcase/nginxpilot:latest
# step 2 — then start quaykeeper beside it
docker pull ghcr.io/kalevski/toolcase/quaykeeper:latest
docker run -d --name quaykeeper \
--network nginxpilot-net \
-p 4100:3000 -p 4101:4101 \
-e QUAYKEEPER_GITHUB_CLIENT_ID="<github-oauth-client-id>" \
-e QUAYKEEPER_GITHUB_CLIENT_SECRET="<github-oauth-client-secret>" \
-e QUAYKEEPER_OAUTH_REDIRECT_URI="http://localhost:4100/api/auth/github/callback" \
-e QUAYKEEPER_AUTH_SECRET="$(openssl rand -hex 32)" \
-v "$HOME/quaykeeper-workspace:/workspace" \
ghcr.io/kalevski/toolcase/quaykeeper:latest
# open Quaykeeper, sign in with GitHub, add the nginxpilot ADMIN_TOKEN as a realm
✓ signed in — you're the owner
